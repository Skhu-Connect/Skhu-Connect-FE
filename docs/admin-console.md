# 성공잇다 관리자 콘솔 소개

**주소** https://petition-system-two.vercel.app/admin

학생이 올린 청원이 공감을 모아 임계치를 넘으면, 그때부터는 학교가 답할 차례다. 관리자 콘솔은
그 "학교가 답하는 쪽"을 담당하는 화면이다. 어떤 청원이 답변을 기다리는지 한눈에 보고, 공식
답변을 달고, 부적절한 글과 댓글을 정리하고, 청원이 전달되는 기준선 자체를 조정한다.

학생 앱과 완전히 분리된 별도 계정 체계로 동작하며, 여기서 한 조치는 곧바로 학생 앱에 반영된다.

---

## 접속과 인증

`/admin/login`에서 관리자 아이디·비밀번호로 로그인한다. 학생 계정으로는 들어올 수 없다 —
백엔드의 관리자 전용 인증 경로(`/connect/admin/auth/login`)를 쓰는 독립 계정이다.

- 로그인하지 않은 상태로 `/admin` 하위 어느 주소로 들어와도 로그인 화면으로 되돌린다.
- 새로고침해도 로그인이 풀리지 않는다. `adminRefreshToken` 쿠키로 세션을 복구하며, 복구를
  마치기 전까지는 화면을 그리지 않아 로그인 화면이 잠깐 스쳐 보이는 일이 없다.
- 로그인 실패 문구는 항상 "아이디 또는 비밀번호가 올바르지 않습니다." 하나다. 아이디가
  존재하는지 여부를 문구 차이로 흘리지 않기 위해서다.

좌측에는 232px 고정 사이드바가 있고 본문만 스크롤된다. 메뉴는 대시보드 · 청원 관리 ·
카테고리 담당자 · 임계치 설정 · 신고 관리 · 알림 로그 6개이며, 하단에 관리자 프로필과
로그아웃이 있다.

---

## 1. 대시보드 — 지금 무엇을 해야 하는가

로그인하면 처음 만나는 화면이다. 상단 통계 카드 4장으로 전체 상황을 요약한다.

| 카드 | 의미 |
|---|---|
| 전체 청원 | 등록된 청원 총 건수 |
| 임계치 도달 · 검토 필요 | 공감이 기준을 넘었는데 아직 답변이 없는 건수 |
| 답변 완료 | 공식 답변이 등록된 건수 |
| 누적 공감 | 모든 청원의 공감 수 합계 |

네 숫자는 모두 청원 목록에서 그때그때 계산한다. 답변을 하나 달면 "검토 필요"가 줄고 "답변
완료"가 느는 것이 즉시 보인다.

검토가 밀린 청원이 하나라도 있으면 통계 아래에 **"N건이 임계치를 넘어 담당자 검토를 기다리고
있습니다"** 배너가 뜬다. 처리할 일이 없으면 배너도 없다.

그 아래에 전체 청원 테이블이 놓인다.

---

## 2. 청원 관리 — 찾아서 처리하기

대시보드가 "전체"라면 이 화면은 "골라내기"다. 세 조건을 동시에 걸 수 있다.

- **상태** — 전체 / 접수 / 검토중 / 답변 완료
- **카테고리** — 전체 + 카테고리 5종
- **검색** — 제목 부분 일치

세 조건은 AND로 묶이고, 결과 건수가 테이블 제목에 그대로 표시된다("청원 12건"). 조건에
맞는 청원이 없으면 필터를 바꾸라는 안내가 나온다.

---

## 3. 청원 테이블 — 콘솔의 중심

대시보드와 청원 관리가 함께 쓰는 5열 테이블이다. 실제 작업은 대부분 여기서 일어난다.

| 열 | 내용 |
|---|---|
| 제목 / 담당 | 청원 제목, 숨김 상태 배지, 담당 부서·담당자 |
| 카테고리 | 카테고리 태그 |
| 상태 | 접수 / 검토중 / 답변 완료 |
| 공감 / 임계치 | 진행바 + 달성률(%) + `현재 / 목표` + 산정 기준 |
| 처리 | 행 단위 액션 버튼 |

진행바는 임계치에 도달하면 색이 바뀌어 처리 대상임을 드러낸다.

**행 액션 3종**

1. **답변 작성 / 답변 완료 · 보기 / 대기중** — 임계치에 도달해야 답변 버튼이 활성화된다.
   기준에 못 미친 청원은 "대기중"으로 비활성이라, 아직 답할 때가 아닌 글에 실수로 답변이
   달리지 않는다. 이미 답변한 청원은 "답변 완료 · 보기"로 바뀌어 열람·수정 진입점이 된다.
2. **댓글** — 해당 청원의 댓글 관리 모달을 연다.
3. **숨김 / 복원** — 청원 자체를 학생 화면에서 감추거나 되돌린다. 숨길 때는 사유 입력이
   필수이고, 복원은 확인을 한 번 받는다. 숨겨진 청원은 목록에서 사라지지 않고 "숨김" 배지가
   붙은 채 남아 관리자는 계속 볼 수 있다.

### 답변 작성 모달

청원 제목·카테고리·상태·담당자와 본문 요약을 위에 띄워 두고, 아래에서 답변을 작성한다.

- **답변 주체** — 운영팀 답변 / 학교 공식 답변 중 선택
- **공식 답변** — 최대 1,000자

신규 등록 버튼은 "답변 등록 · 상태 변경"이다. 이름 그대로 답변을 저장하는 동시에 청원 상태를
'답변 완료'로 옮긴다. 이미 답변한 청원에서 열면 기존 답변을 서버에서 불러와 채운 뒤 "답변
수정"으로 저장한다.

기존 답변을 불러오지 못하면 **입력 폼을 아예 띄우지 않고** 경고와 재시도 버튼만 보여준다.
빈 칸을 진짜 빈 답변으로 오해한 관리자가 새로 써서 저장하면 원래 답변이 조용히 사라지기
때문이다. 이 상황에서는 저장 자체를 막는다.

Esc로 닫히고, 닫으면 모달을 연 버튼으로 포커스가 돌아간다.

### 댓글 관리 모달

청원 하나에 달린 댓글과 대댓글을 한 목록으로 펼친다.

- 작성자는 익명 번호로만 표시된다(청원별 영구 번호). 답글에는 `↳` 표시가 붙는다.
- 댓글별로 **숨김**(사유 필수) · **복원**을 개별 실행한다.
- 숨긴 댓글은 목록에서 사라지지 않고 취소선과 함께 숨김 사유가 같이 보인다. 왜 가렸는지가
  화면에 남아야 다음 사람이 판단할 수 있다.

---

## 4. 카테고리 담당자 — 누구에게 가는가

임계치를 넘은 청원의 검토 요청이 어느 부서, 누구에게 가는지 보여주는 카드 목록이다.
카테고리마다 한 장씩이며 담당자 이름, 소속 부서, 이메일, 전화번호가 들어간다.

카드 하단에는 그 담당자에게 걸린 부하가 표시된다 — **담당 청원 N건**, **검토 대기 N건**.
대기 건이 있으면 색으로 강조돼, 어느 부서가 밀려 있는지 한눈에 드러난다.

---

## 5. 임계치 설정 — 기준선 자체를 조정

"공감 몇 명부터 학교로 전달할 것인가"를 정하는 화면이다. 카테고리마다 세 값을 조회·수정한다.

- **전체 학생 수** — 비율 계산의 모수
- **임계치 비율(%)** — 0.01% 단위
- **최소 인원** — 비율로 계산한 값이 너무 작을 때의 하한선

이 셋으로 계산된 **목표 공감 수**가 함께 표시된다. 실제로 청원이 넘어야 하는 숫자다.

수정하려면 **변경 사유를 반드시 적어야 한다.** 사유가 비어 있으면 저장 버튼이 잠긴다. 저장된
사유는 카드에 "최근 변경"으로 남아, 기준이 왜 지금 값인지 나중에도 추적된다.

여기서 바꾼 값은 학생 앱에도 바로 반영된다 — 청원 등록 화면의 임계치 안내와 상세 화면의
진행바가 같은 출처를 읽기 때문이다.

---

## 6. 신고 관리 — 신고를 판정하기

학생이 신고한 글과 댓글을 검토해 결론을 남기는 화면이다. 필터는 세 가지다.

- **상태** — 전체 / 대기 / 조치 완료 / 기각
- **대상** — 전체 / 글 / 댓글
- **검색** — 글 제목 또는 신고 사유

각 행에는 신고 대상(청원 제목, 글 신고인지 댓글 신고인지), 신고 사유 유형, 신고자가 적은
상세 사유가 들어간다. 사유 유형은 광고·도배 / 욕설·괴롭힘 / 부적절한 콘텐츠 / 허위 정보 /
기타 5종이다.

대기 중인 신고에는 **조치 완료**와 **기각** 두 버튼이 있고, 어느 쪽을 누르든 이유를 적어야
처리된다. 처리한 신고는 버튼이 사라지고 결과와 그때 적은 이유가 행에 남는다. 판정만 남고
근거가 사라지는 일이 없도록 한 것이다.

실제 글·댓글을 가리는 것은 청원 테이블과 댓글 관리 모달의 숨김 기능이 맡는다. 이 화면은
"신고를 어떻게 판정했는가"의 기록을 담당한다.

---

## 7. 알림 로그 — 무엇이 언제 나갔는가

담당자에게 발송된 알림 이력이다. 세 종류를 색과 아이콘으로 구분한다.

- **임계치 도달** — 청원이 기준을 넘어 검토 요청이 나간 시점
- **답변 등록** — 공식 답변이 달려 학생에게 통지된 시점
- **리마인더** — 처리가 지연된 건에 대한 재알림

항목마다 청원 제목, 카테고리, 알림 문구, 발송 시각이 붙는다. "연락 못 받았다"는 말이 나올 때
확인하는 화면이다.

---

## 학생 앱과 어떻게 이어지는가

관리자 콘솔의 조치는 학생 쪽에서 이렇게 나타난다.

| 관리자가 한 일 | 학생 쪽 결과 |
|---|---|
| 공식 답변 등록 | 청원 상세에 답변이 붙고 상태가 '답변 완료'로 바뀌며 푸시 알림 발송 |
| 청원 숨김 | 학생 목록·상세에서 제외 |
| 댓글 숨김 | 해당 댓글이 학생 화면에서 가려짐 |
| 임계치 변경 | 등록 화면의 기준 안내와 상세 진행바가 새 기준으로 표시 |

관리자가 답변을 다는 순간이 학생 앱 푸시가 나가는 순간이다. 두 화면은 같은 데이터를 본다.

---

## 현재 상태

로그인, 청원 목록, 공식 답변 등록·수정·조회, 청원·댓글 숨김·복원, 댓글 조회, 신고 처리,
임계치 설정은 모두 실제 서버와 연동돼 동작한다.

**카테고리 담당자 정보와 알림 로그 두 화면은 아직 고정 데모 데이터로 표시된다.** 대응하는
백엔드 엔드포인트가 없어서이며, 화면과 데이터 계약은 이미 만들어져 있어 엔드포인트가 나오면
그 자리만 바꾸면 된다. 현재 표시되는 담당자 5명은 가상 인물이고 연락처는 자리표시자다.
